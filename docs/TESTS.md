# Causalab Testing Conventions

Causalab is a codebase for trusted mechanistic interpretability experiments. It contains tested primitives of interpretability methods, expressed as serializable intervention specifications (docs/intervention_protocol.md) executed by engines. The tests must be held to a high standard to create confidence in the results. Trustworthiness and reputation is the most valuable asset of us researchers, we need to back it up with consistently correct experiments.


## Quick Start

Run all CPU tests via `uv run pytest -m "not golden"` (what CI runs). `uv run pytest -m golden` runs only the golden tier, which needs an accelerator and real model weights (see [Golden](#golden)).

## Overview of test types

Every test belongs to exactly one tier, declared via a pytest marker. The five markers fall into two families: **unit tests** — CPU-only, fast, narrow functionality (`numerical_unit`, `property`, `unit`) — and **end-to-end tests** — user-facing behavior through the real CLI (`smoke`, `golden`).

## Conventions

### Mocking policy

1. **Tiny real over mocks.** Use the smallest real implementations: `hf-internal-testing/tiny-random-*` checkpoints instead of mocking a neural network, tiny committed fixture datasets, ...
2. **Mock only at system boundaries.** Reserve mocks for transactional dependencies CI shouldn't hit: HTTP APIs, paid services, time/random, forced error paths. (The CLI's lazily-imported execution engine is stubbed via `sys.modules` in `tests/protocol/test_cli.py` — the same idea.)

### Unit tests

1. **Test file location.** A test for `causalab/<subdir>/<stem>.py` belongs at `tests/<subdir>/test_<stem>.py`. Tier is declared via marker (`pytestmark = pytest.mark.<tier>`, at module, class, or function scope).
2. **One class per tier.** A single file may hold multiple tiers; the typical pattern is one class each.
3. **Task numerical pin.** Guard each task with an LM-free symbolic pin on a task's `CausalModel` and counterfactual generator, as a sidecar `tests/tasks/<task>/pinned_samples.json`. Update via `scripts/update_task_pins.py --task=<name>`, review the diff, then if correct rerun with `--i-have-reviewed-the-diff`.
4. **One compiler, four doors.** `tests/protocol/test_compile_protocol.py` compiles the divergence case — a document in a sibling directory with a `set` override and a step-emitted (deferred) artifact — through the CLI, `run_protocol`, a workflow step and workflow validation, and asserts the canonical form, point list and digests are byte-identical across all four (IM spec §9.1). The same file is the census for the compiler's stage list and diagnostic kinds against the spec's tables, and the grep-proof that no module outside `causalab/protocol/compile.py` composes the pipeline. A change to the load order is a change to that table, not a refactor. `tests/protocol/test_legality_before_weights.py` is the acceptance suite for §5's invariant (legality decided before weights load): one refusal test per document-decidable refusal, its valid-work twin, and the never-called-loader assertion — every refusing document through `run_protocol` with the reference engine's `load_model` monkeypatched to raise, so the refusal is shown to come before any weights. `tests/protocol/test_paths.py` is the `paths` stage (IM spec §3.2): the shipped `path_patching.json` re-expressed as a `method.path_patching` block compiles **byte-identically** to the hand-written document (T11) and the block form of the `03_path_patching_im.json` corpus document reproduces its pinned digest; a one-element receiver set is the scalar document (T9); two blocks differing only in `restoration` have different point digests, with the policy legible off the compiled form and the receipt's `derived` block (T10); no shipped or corpus document lowers anything (T12); and every block refusal (`P2`/`P3`/`P4` naming `method.path_patching.<field>` — including the address-level collision check over every emitted site, each refusal beside the valid-work twin that lowers — rule 3 on the lowered document, an authored table that is not an object refused `P2` by its path rather than reaching an assertion, `--set` into the block refused as a path that does not exist). `tests/neural/engines/pytorch_hooks/test_paths_run.py` is its engine half: two receivers injected in one `final` forward group — the receipt's `fires` block lists both `inject_*` members under one label — whose joint effect is not the sum of the two single-receiver runs because the receivers nest — the joint pass equals the upstream-only run and the sum counts the downstream effect twice (the nesting asserted separately as structure and as numbers, so the sum-of-separate-runs mutation cannot pass vacuously; ### Golden

The sole accelerator tier, under `tests/golden/`. Seven `golden`-marked suites (beside the CUDA-graph suites `test_cuda_graphs.py`, `test_graph_cohort.py`, `test_graph_reuse.py`, `test_cayley_capture.py`),
the first two with **opposite provenance rules**, the third and fourth needing no
external provenance at all, the fifth certifying against an independent oracle, and the sixth reproducing the readout adapter's residual accounting:

1. **Paper goldens** (`tests/golden/test_paper_goldens.py`): intervention specifications on real open models (gpt2, gpt2-xl, Llama-3.1-8B, gemma-2-2b-it), asserted against values from **published papers** (`tests/golden/paper_goldens.json`, one provenance entry per value — paper quote, sidedness, band/floor). No value in that file may come from running this stack. Fixture datasets are seeded, committed JSON from `tests/golden/fixtures/generators/`.
2. **Drift pins** (`tests/golden/drift/`): the successor of the retired chat-coherent tier — Qwen3-4B documents whose values **are** pinned from a reviewed run of this stack on one CUDA machine (`tests/golden/drift/update_drift_goldens.py --i-have-reviewed-the-diff`), replayed within tolerance for run-to-run drift detection. Baseline gate: accuracy ≥ 0.9. The first capture has landed — `drift_goldens.json` carries 16 values (`interchange.acc.mean` 1.0, `interchange.iia.mean` 0.421875, a 7-point layer scan) — so the replay now skips only for want of cuda, never for want of pins. Fidelity gap vs the retired tier, recorded here: protocol v1 has no chat-template path, so the drift documents use raw completions (the old tier's chat template + answer directive is not reproduced). The extractor's label grammar is a CPU-guarded contract: `_META_COLUMNS` in `tests/golden/drift/_extract.py` names every per-row column that is not a sweep axis (the row keys, the provenance stamp, the reduction record's identity `unit` / `estimand_version`, the eligibility record `eligible` / `reason_code`, the windowed-read columns `step` / `matched`), and `tests/golden/drift/test_extract_labels.py` (tier `unit`) pins that the labels are the sweep coordinates alone and match the pinned key set; a non-finite measurement (a coordinate whose rows are all excluded) is a replay mismatch, never a silent pass, and the capture refuses to write it.
3. **Engine parity** (`tests/golden/test_a3b_engine_parity.py`): the two engines' answers over the shared component vocabulary, read and written, on the real `Qwen/Qwen3.6-35B-A3B` — 40 layers, 256 experts routed top-8, bf16. It pins nothing external: the two engines are each other's oracle, which is why it has no provenance file. Each engine captures the whole sweep in turn and is then freed, so one ~70 GB model is resident at a time rather than two. On the real checkpoint all 111 compared cases agree at max abs diff **exactly 0.0**; `ATOL` is kept at 1e-2 as a band against a future kernel change, well under one bf16 ulp at this model's logit magnitude. Its tiny-fixture half is the smoke-tier `tests/neural/engines/nnsight_tracing/test_parity_a3b_sweep.py`.
4. **The inventory** (`tests/golden/test_a3b_inventory.py`): `registry.inventory` on the loaded `Qwen/Qwen3.6-35B-A3B` — 40 attention and 40 MLP components, 10 full-attention and 30 DeltaNet layers, invalid stream × site combinations refused — against the offline inventory of the registry entry, layer for layer. The tiny tier is `tests/neural/engines/pytorch_hooks/test_family_plugin.py`.
5. **Family oracle certification** (`tests/golden/test_family_certification_a3b.py`): the real `Qwen/Qwen3.6-35B-A3B` in bf16 against the *independent* raw-hook oracle — not the other engine — over the same case table as the CPU family (`tests/neural/parity/family_certification.py`): module-boundary reads on a DeltaNet and a full-attention layer, the kernel's argument slots, the recurrence interior (`delta_state`, `delta_kv_mem`, `delta_state_update`) read and written, interchange writes compared on the patched logits **and** a downstream intermediate, and the anti-vacuity pair (a genuine write moves the compared tensors; a no-op is bit-exact, the state's no-op being the bounded path-forcing drift). It replays `tests/neural/parity/goldens/qwen36_a3b.json`, the family capture with the certification record's eight fields, at the bf16 band the record justifies by measurement. One model resident, by the module-boundary eviction in `tests/golden/conftest.py` (below).
6. **The readout adapter** (`tests/golden/test_readout_a3b.py`): the residual accounting on the real `Qwen/Qwen3.6-35B-A3B` in bf16 through `causalab/neural/shared/readout.py` — `Readout.logits(block_output@39)` equal to the engine's `lm_head` read bit for bit, the fixed-RMS decomposition of the logits over `block_input@0` and the 80 attention / MLP components closing at the fp64 reference projection's noise floor with the two declared rounding terms (normalization, LM head) and breaking by exactly the dropped term without either, each term within the declared band of bf16 roundoff at its value's magnitude, and the `one_plus_weight` gain certified against the norm module's forward. The same accounting and assertion shape as the CPU tier (`tests/neural/shared/test_readout.py`, via `tests/_helpers/readout_accounting.py`); it pins no number — the fp64 noise floor and the two dropped-term breaks are the shape it expects. One model resident, by the module-boundary eviction in `tests/golden/conftest.py` (below).
7. **The fused MoE glue kernels** (`tests/golden/test_moe_glue_kernels.py`): the Triton kernels around the grouped-experts GEMMs (`pytorch_hooks/kernels/`) held to `torch.equal` on the device, in three layers — the ATen orders `moe_glue_reference.py` states (the stable sort above 32 keys, the index backward's fold and rounding by width, the slot sum's four accumulators, the row sum's lanes and tree) against the library ops; each kernel against its reference; and the fused experts path against `grouped_mm_experts_forward` in output and every gradient (hidden states, routing weights, both expert weights) on the workflow's shapes (S = 9 984 / 4 368 / 93 600) and small odd ones, in bf16 / fp16 / fp32, with the default kernel set, with the gate kernel on, and captured in a CUDA graph and replayed. No model weights: synthetic experts modules. It skips without CUDA or Triton; a failure prints the differing count and the largest gap.

Practicalities:

- Run with `uv run pytest tests/golden -m golden` on a box with an accelerator. Gated models (`meta-llama/Llama-3.1-8B`, `google/gemma-2-2b-it`) need a licensed `HF_TOKEN` — without one the load 401s with nothing naming the cause.
- The reference engine runs each (model, input) forward group as **one batch** unless `--batch-rows N` bounds the rows per forward (spec §8, execution scale; the numbers equal the single-batch run up to dtype rounding and the digests are unaffected). Whole, the largest paper-golden document (hours, 1,152 rows on Llama-8B) wants ~35GB free in bf16.
- A CPU structural guard (`tests/golden/test_structural.py`, tier `unit`, runs in CI) keeps the tier honest without loading models: documents load and digest to their pins, every non-pending goldens entry is claimed by exactly one test, provenance fields are present.
- VRAM reclamation, two layers: `tests/conftest.py::pytest_runtest_teardown` runs `gc.collect()` + `torch.cuda.empty_cache()` after every `golden`-marked test, which frees *dead* models only; and `tests/golden/conftest.py::_one_model_resident`, an autouse module-scoped fixture on every `golden`-marked module, calls `tests/_helpers/resident_models.py::evict_resident_models` — both engines' `load_model` caches (`functools.lru_cache(maxsize=4)`) cleared, then collect, then `empty_cache` — before the module's first fixture and after its last is finalized, so a module never inherits the models the previous one loaded (the golden tier runs as one process, one accelerator, modules in collection order). A module fixture that loads a model needs no teardown of its own. The tier's budget is therefore *one module's* models; a module that needs the whole card (the `Qwen/Qwen3.6-35B-A3B` suites, ~70 GB) fits regardless of what sorted before it — `test_readout_a3b.py` sorts after the paper goldens' GPT-2 XL and Llama-3.1-8B and ran out of memory to exactly that before the boundary owned it. The CPU guard is `tests/golden/test_resident_models.py` (`unit`): against fresh loader caches, a cached tiny model is gone after the eviction and the next call is a fresh load.

## CI

CI runs two jobs on every pull request, on CPU runners:

1. **`lint`** — `uv run --frozen --only-group lint pre-commit run --all-files`
   (ruff + the stack). The `--only-group lint` is load-bearing on both the sync
   and the run: a bare `uv run` would re-sync the default groups and drag in the
   whole torch stack just to put `pre-commit` on PATH. Run pre-commit in the same
   command as your commit so a reformat never lands after it.
2. **`test`** — `uv run pytest -m "not golden"` over the CPU tiers (`unit` /
   `numerical_unit` / `property` / `smoke`). Beside it, the Rust core's own
   checks (`cargo fmt --all -- --check`, `uv run cargo clippy --workspace
   --all-targets -- -D warnings` — under `uv run` so pyo3's build script sees a
   Python ≥ 3.10 — and `cargo test` over the pure crates `fst-core` / `fst-cuda`;
   `docs/fastersafetensors.md`); the Rust version `rust-toolchain.toml` pins is
   installed first, since `uv sync` compiles the extension. The Python half of
   that core is `tests/io/fastersafetensors/` (tiers `unit` and `property`); its
   `cuda` marker is a hardware marker, not a tier, and its conftest skips it
   where there is no CUDA device. The GPUDirect Storage tests are Rust
   (`crates/fst-cuda/tests/cuda_node.rs`), ignored unless `FST_CUDA_TESTS=1`.

The `golden` tier is the sole accelerator tier and is not part of the CPU pull-request pipeline: it needs an accelerator and real model weights. Run it on a GPU machine with `uv run pytest -m golden` (see [Golden](#golden)).
